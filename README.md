# Study Gadget キャラクター版

HOMEメニュー用アイコン・動く3Dバナーの素材と、PCへのツール導入・変換・CIA作成・実機確認の手順は [home-menu/README.md](home-menu/README.md) にあります。アイコン付き3DSXはビルド済みです。CGFXの接続・両面補正、バイナリ検査とCIA生成まで完了しています。CIAは `release/cia/studygadget.cia` です。実機での表示・起動は未確認です。

3DSタイマーとAndroid親機を拡張した実装です。元の `3dmodels/ガラクタ/ガラクタ.blend` は変更していません。

## 使い始める

1. `release/sd` の **中身** を3DSのSDカードのルートにコピーします。
2. Androidに `release/StudyCompanion-character-debug.apk` をインストールします。設定で親機サーバーを開始してください。
3. 親機のペアリング設定を、SDカードの `/3ds/studygadget/config.txt` に1行で保存します。書式は `IPまたはauto ポート トークン`。設定画面からファイルを書き出せます。`config.example.txt` は通常のWi-Fi、`config.hotspot.example.txt` はテザリング用の見本です。
4. Homebrew Launcherから `/3ds/studygadget/studygadget.3dsx` を起動します。
5. 3DSのSYNCで学習記録・科目・キャラクター更新を取得します。キャラクターだけは起動中10分ごとに別スレッドでも確認します。

タイマー・ポモドーロ・ストップウォッチ、科目切替、SD記録、Androidへの記録同期は既存機能を引き継いでいます。オフラインでもキャラクターとタイマーは動きます。3DSを閉じたり電源を切ったりしている間の受信は行いません。

## 親機スマホのテザリングで使う（1.2）

1. **Android版と3DS版の両方を新しいものに更新**します。古い3DS版は `auto` を解釈できません。
2. 親機AndroidのWi-Fiテザリングを有効にし、2.4GHz（互換モード）・WPA2パーソナルに設定します。5GHz専用・WPA3専用では3DSを接続できません。
3. 3DSの本体設定 → インターネット設定で、そのスマホのSSID・パスワードを登録して接続します。
4. 親機アプリの設定 → ペアリング設定 → **親機スマホのテザリング（IP自動）**を選び、**3DS用config.txtを保存**を押します。
5. 保存したファイルを3DSのSDカードの `/3ds/studygadget/config.txt` に置きます。例は次のとおりです（トークンは親機アプリの実際の値に置き換えます）。

```text
auto 8765 YOUR_PHONE_PAIRING_TOKEN
```

6. 親機アプリのサーバーを起動して、3DSアプリでSYNCします。下画面の `PHONE AUTO` に、実際に使った親機IPが表示されます。

3DSは接続先のデフォルトゲートウェイを取得し、それをテザリング元の親機として扱います。`192.168.43.1` などの固定値を仮定しません。テザリングの再起動でサブネットが変わっても、各通信で再取得します。端末の制約でスマホ自身がテザリング側IPを列挙できなくても、設定は `auto` のままで使えます。

通常のWi-Fiルーターに3DSと親機を両方つなぐ場合は「同一Wi-Fi・IPを指定」を選び、親機のIPを指定します。その構成で `auto` を使うとルーターを接続先としてしまいます。モバイル回線やVPNのIPは接続先候補から除外しています。

記録・科目・キャラクターの同期はスマホと3DSのローカル通信です。AIリレーへの生成リクエストは、設定したリレーへの接続が別途必要です。実機のテザリングでの疎通確認は未実施です。


## 3DSの黒画面対策・通信状態表示（2.1）

`release/sd/3ds/studygadget/studygadget.3dsx` をSDの同じ場所へ上書きしてHBLから起動します。既存の `config.txt` や学習記録はそのまま使えます。

- 最初に起動メッセージとUIを描画し、その後にSD設定・キャラクター・モーションを段階的に読み込みます。Wi-Fi初期化・通常のHTTP送受信はUI表示後のワーカースレッドで行います。
- 下画面の `BOOT` は起動段階、`NET` はWi-Fi初期化・接続・送信・応答待ち・結果を表示します。通信中は経過秒数と上画面の点滅インジケーターが動きます。`CHAR` は更新確認・モデル/モーションの受信KB数・適用・更新失敗を表示します。
- 通常HTTPは1リクエスト全体で8秒を上限とします。モデルなどの大容量更新は既存の最大45秒/転送（接続待ち最大3秒）を使用し、UIとは別に動きます。接続失敗後もタイマーを使用でき、`SYNC` で再試行できます。
- 認証エラー（HTTP 401/403）、接続拒否、ゲートウェイ未取得、タイムアウト、通信初期化エラーを区別します。`auto` のテザリング設定も使用できます。
- **Xを押しながらHBLで起動**するとキャラクター読込と更新を省略します。これで起動する場合はモデル・描画側に原因を絞れます。通常起動後のXはキャラクター表示の切替、SELECTは終了です。
- `/3ds/studygadget/boot.log` に起動段階と通信結果を残します。前回分は `boot.previous.log` に保持します。トークンや学習記録の本文はこのログへ出力しません。
- 未送信記録は送信用の `pending.upload` と新規記録用の `pending.jsonl` に分け、バッチ全件の成功後に送信用ファイルを削除します。通信失敗・終了・中断時は記録を保持し、再送の重複はAndroid側の既存ID判定で除きます。

検証：3DS向けビルド、実際のC通信処理を使った17ケースの模擬I/Oテスト（無応答8秒・低速応答・認証失敗・途中切断・キャンセルなど）。実機での起動・描画・Wi-Fi動作は未確認です。まだ止まる場合は、最後に表示された `BOOT` / `NET` の内容と `boot.log` を確認してください。

## キャラクター

- `character/character-renamed.blend`: リネーム済みのリグとモデル。23ボーン、2,772三角形。
- `character/character-motions.blend`: 48個の編集可能なBlender Actionsを追加した版。アクション選択で確認できます。
- `character/bone-map.json`: 元の名前と新しい名前、追加した部品の追従先。
- `character/preview.png`: 書き出したデータを直接読んだソフトウェアプレビュー。実機スクリーンショットではありません。

`hips / spine / chest / neck / head / shoulder.L / upper_arm.L / forearm.L / hand.L / upper_leg.L / lower_leg.L / foot.L` と左右、髪の名前を採用しています。孤立していた脚をhipsへ接続し、追従設定のなかった部品は近いボーンへの剛体追従を追加しています。細かな衣服のウェイト調整はBlenderで継続できます。

3DSでは4ウェイトのCPUスキニングとGPUのテクスチャ・深度描画を行います。生成した動作は待機・集中・休憩・達成・応援・睡眠の6状態×8種類です。集中中は小さな動作、達成時は腕の動作、夜間は睡眠動作へ変わります。0.8秒で動作をつなぎ、同じ状態でも一定間隔でパターンを変更します。

## 背面法とモデルの更新

**反転外殻メッシュを残したまま書き出せます。** Solidify / Mirrorなどは書き出し時に評価します。裏面を消すか両面を描くかを素材ごとに保持します。Blenderのマテリアルのカスタムプロパティに文字列 `sg_cull` を指定すると、明示的に制御できます。

| sg_cull | 3DSでの表示 |
|---|---|
| `none` | 両面。薄い髪や板ポリゴン用 |
| `back` | 裏面を消す。法線を反転した黒い外殻の背面法にも使用 |
| `front` | 表面を消す。法線を反転していない外殻用 |

未指定ならBlenderのBackface Culling設定を採用します。名前に `outline` / `輪郭` / `ふち` / `外殻` を含むオブジェクト・素材も `back` にします。輪郭用外殻は少し膨らませ、黒い素材を割り当ててください。透明面はアルファテスト（約3%以下を破棄）で、半透明の重なりやBlender固有の光沢・影を完全に再現するものではありません。色ノードの出力を直接Surfaceへつないだ素材も、実際に接続されている出力を採用します。

モデルを書き直したら、プロジェクトルートで実行します。

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup '.\character\character-renamed.blend' --python .\tools\export_character.py -- '.\character-update'
```

新しい `character-update/model.sgch` をスマホへ渡し、設定の「モデル更新」で選択してください。そのモデルに合う48パターンを自動的に作り直します。3DSでSYNCするか、自動更新を待ちます。骨格IDが合わない動作は適用しません。モデル上限は96ボーン・8,000三角形・4ウェイト・1,024角テクスチャ・ファイル8MiBです。現在のモデルは約4.45MiBです。

## Androidホーム画面ウィジェット（1.3）

`release/StudyCompanion-character-debug.apk` を更新インストールし、アプリの設定 → 「ホーム画面にキャラクターを追加」を押します。追加確認が出ないランチャーでは、ホーム画面を長押し → ウィジェット → Study Companion → 「学習キャラクター」を配置してください。元のAndroid Studioプロジェクト位置は `assets` のままです。

- キャラクター／下の動作番号をタップ：現在の状態内で次のモーションへ。
- 状態名をタップ：自動 → 待機 → 集中 → 休憩 → 達成 → 応援 → 睡眠 → 自動。
- 「静止」／「再生」：アニメーションと静止画を切り替え。タイトルでアプリを開きます。
- ウィジェットごとに状態・動作番号・静止設定を保持し、縦横にサイズ変更できます。

自動モードでは3DSからの学習開始で集中と経過時計、終了で達成に変わります。終了後30分以降は待機、23〜7時は睡眠になります。状態変化は学習イベント、タップ、モデル／モーション更新時とAndroidの定期更新（約30分、OS次第で遅延）で反映します。経過時計はランチャー内で進みます。ライブ開始から12時間を過ぎた表示は次回更新時に解除します。

3DSと同じSGCHモデル・SGMOモーションバンクを端末内で読み、4ウェイトの骨格変形・テクスチャ・透明部分・素材ごとのカリングを反映した24フレームを生成します。ホーム画面では128×160のフレーム列をループ再生します。3DSのリアルタイム3D描画とは異なり、速さは約1〜12fps（動作設定による）です。動作パターンはタップまたは次回更新で切り替わり、毎秒別の動作を生成する処理ではありません。夜間生成やモデル交換後は配置済みウィジェットも更新します。再生だけなら親機サーバーの常時起動は不要です。3DSからの学習開始・終了の受信にはサーバー起動が必要です。

描画は更新イベント時だけ行い、再生のための常駐サービス・毎フレーム通信・厳密アラームは使いません。静止表示はタイマーのないレイアウトです。Androidの画像メモリ上限を考慮し、再生用画像は合計1.875MiBに固定しています。描画失敗・時間超過時は静止プレビューと再試行ボタンを表示します。実際のランチャーでの再生・省電力時の挙動は端末で確認が必要です。

## 夜間生成とAI

設定の「夜間・充電中に自動生成」が有効なら、AndroidのJobSchedulerが充電中の0〜7時に最大1日1回実行します。実行時刻はOSと省電力設定によって前後し、必ず指定時刻に起動する保証はありません。充電解除・高温・キャンセル時は更新を中断します。

AIリレーURLが空欄なら、通信も料金も不要なプロシージャル生成です。**スマホに学習済みLLMやテキストからモーションを直接生成するモデルは搭載していません。** AI連携時もLLMが安全なパラメータを提案し、実際の関節変形は3DSのアニメーション処理が合成します。Blender Actionsの任意のキーフレームを直接ネット配信する方式ではありません。

API連携用の実装は `tools/motion_gateway.py` です。ChatGPTのこの会話・Plus契約をそのままアプリへ埋め込む連携ではなく、別途設定するAPI連携です。APIへの有料リクエストはまだ実行していません。

1. サーバー側で `MOTION_RELAY_TOKEN`（24文字以上）、`MOTION_MODEL`（Structured Outputs対応のモデルID）、`OPENAI_API_KEY` を環境変数として設定します。
2. `python tools/motion_gateway.py` でlocalhost:8788を起動します。
3. 自分のHTTPSリバースプロキシなどで `/generate` に接続できるようにします。
4. 親機設定のAIリレーURLへ `https://自分の接続先/generate`、リレー認証トークンへ `MOTION_RELAY_TOKEN` を入力し、「接続設定を保存」→「今すぐ生成」。

OpenAIのAPIキーはAPKへ入れません。`MOTION_LLM_URL` を設定すればOpenAI互換APIを持つローカル推論サーバーもリレーのバックエンドとして使えます。スマホ自身に置く場合は、別途ローカル推論サーバーの導入が必要です。親機のURLはHTTPSまたは端末内 `http://127.0.0.1` / `http://localhost` に限定しています。

AIの応答は値の範囲と6状態の網羅を検証し、失敗したら既存モーションを保持します。生の勉強記録やモデルのメッシュはAIへ送りません。送るのは直近7日間の合計秒数・時刻などの生成条件です。

## ビルド・検証

```powershell
# 3DS（devkitPro導入済みWindows）
.\tools\build-3ds.ps1
# モデルをSD用とAndroid同梱用に配置
python .\tools\package_character.py
# バイナリ・骨格変形・生成条件の検証
python .\tools\test_character.py
# ソフトウェアプレビュー（NumPy/Pillowが必要）
python .\tools\preview_character.py
```

Androidは `assets` をAndroid Studioで開き、JDK17、Android SDK35でビルドします。追加のUnity・有料アドオンは不要です。

### サーバー起動修正版（1.1.1）

Wi-Fiロックに必要な `WAKE_LOCK` 権限を追加し、サーバーの初期化前にフォアグラウンド通知を開始するように修正しました。`specialUse` タイプの指定はAndroid 14以降に限定し、起動失敗はホーム画面に表示します。

ビルドはGradle 8.13 / AGP 8.13.2 / Kotlin 2.1.0 / KSP 2.1.0-1.0.29 / Hilt 2.55 / JDK17の組み合わせに固定しています。Android Studioでは元の `assets` を開いて再同期してください。Upgrade Assistantによる一括更新後の設定は `diagnostics/build-config-before-server-fix` に退避しています。KotlinとHiltのメタデータ互換性を確認するまで一括更新は適用しないでください。

このPC用のビルド・検証スクリプトは `tools/build-android.ps1` です。実行環境でGradleワーカーの内部通信が制限されているため、通常のjavacと同じJUnitテストを直接実行する設定を添えています。接続設定・端末内データ形式などをJUnitで検証します。モデル形式・骨格・モーションの検証は `tools/test_character.py` で行えます。

受信ファイルは固定長・サイズ上限・CRC・ボーン階層・ウェイト・有限数を確認します。モデルとモーションの旧版を保持し、途中失敗や不一致時に前のデータを読み直します。アプリを強制終了したりSDを抜いた場合まで含む完全な更新原子性は未検証です。

実機でのフレームレート、3DSのGPU上のカリング方向、Android実機での夜間実行とWi-Fi転送は別途確認が必要です。
