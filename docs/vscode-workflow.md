# VS Codeで3DSのUIを編集して更新する

## 最初に開く
プロジェクト直下の **Open-StudyGadget.cmd** をダブルクリックします。
専用拡張を読み込んだVS Codeが開きます。通常のVS Codeの拡張構成は書き換えません。
表示されないときはフォルダーを信頼し、通知のエラーと「出力 → Study Gadget」を確認します。

普段使うVS Codeへ常設する場合は、拡張機能の「… → VSIXからのインストール」で
release/studygadget-tools-0.1.0.vsix を選択し、ウィンドウを再読み込みしてください。

## ボタン
| ボタン | 動作 |
|---|---|
| 3DS Preview | 右側に上画面400×240・下画面320×240を表示 |
| Build | 保存して3DSXをビルド。Ctrl+Shift+Bでも可能 |
| 3DS更新 | 保存・ビルド・親機へ送信・自動更新予約・3DSの完了報告確認 |

assets/main.c を開いていると、エディター右上にも同じ操作があります。
プレビュー画面内にもビルド・更新・親機設定のボタンがあります。

## UIを触る
1. assets/main.c を開き、draw_top / draw_bottom 内を編集します。
2. Ctrl+Sで保存します。プレビューが再コンパイルされ、状態が初期化されます。
3. 下画面をクリックしてボタンを操作できます。座標も表示します。
4. A=開始/終了、B=停止、X=キャラ表示、Y=科目、L/R=分数変更です。
5. 10倍・60倍で時間を進め、終了やポモドーロの切り替わりを確認できます。
6. 「接続表示を模擬」はオンライン表示の確認用です。スマホへ通信しません。

画面と計測は実際のC関数をホスト側でコンパイルして実行します。
モデルはSGCH、モーションはSGMOを読み、4ウェイト変形と素材ごとのカリングをWebGLで描画します。
モーション選択順は実機と異なります。
字体、GPUドライバー、SDカードへの保存、Wi-Fi、スリープ、実機の処理速度は再現しません。
未知のC2D関数を新しく追加すると、プレビュー用アダプターの追加も必要です。
その場合はCのエラーを表示します。黙って古い画面を出すことはありません。

本格的なエミュレーターを別途導入済みなら、VS Code設定 Study Gadget: Emulator に実行ファイルを指定し、
コマンドパレットの「Study Gadget: 実機エミュレーターを起動」を利用できます。
3DSX対応状況は使用するエミュレーターによります。エミュレーター本体は同梱していません。

## 最初の1回だけ行う実機準備
この自動更新対応コードが古いアプリを後から更新することはできません。
1. release/StudyCompanion-character-debug.apk を親機スマホへ更新インストールします。
2. release/sd/3ds/studygadget/studygadget.3dsx を3DSのSDカードの同じ場所へコピーします。
   既存のconfig.txt、記録、モデルは保持してください。
3. 3DSをHBLから起動します。CIA/HOMEメニューから直接起動した版の自動差し替えは対象外です。
4. スマホ・PC・3DSを同じLAN、または同じ親機テザリングへ接続します。
   テザリングは3DSに対応する2.4GHz/WPA2を利用します。
5. 親機アプリでサーバーを起動します。3DS側config.txtの接続先・ポート・トークンも設定します。
6. VS Codeのプレビューで「親機の設定」を押し、
   http://スマホのローカルIPv4:8765 とペアリングトークンを入力します。
   PCからは auto を指定できません。親機の実IPを指定します。

トークンはVS CodeのSecretStorageに保存し、設定JSON・配布ZIP・URL・ログへ書き込みません。

## 2回目からの更新
「3DS更新」を1回押します。

保存 → 3DSビルド → 親機の既存アップロードAPIへ送信 → SHA-256で同じファイルを指定して自動更新を予約
→ 3DSが約5秒ごとに確認 → 待機中に受信・検証 → バックアップを保持して差し替え → 完了報告
→ 対応するRosalina/HBL環境で再起動を試行、という流れです。

計測中はUPDATEチェック・ダウンロード・インストールを保留します。タイマーを停止すると進みます。
対応するHBL環境がない場合は、更新後にEXITしてHBLから再起動してください。
親機への送信成功と、3DSのインストール完了報告は区別して表示します。
2分以内に完了報告がなければ「未確認」と表示し、予約は最大1時間保持します。
失敗時は3DSのAPP欄と /3ds/studygadget/boot.log を確認してください。
同じビルドを再送しても、新しいコマンドとして確認し直せます。

## 開発環境
このPCで確認した構成：
- Windows / devkitPro: C:\devkitPro
- Python 3
- Visual Studio C++ Build Tools（MSVC / vcvars64.bat）
- Android Studioプロジェクト位置は assets のまま

Pythonのパスは Study Gadget: Python、devkitProの場所は Study Gadget: Devkit Pro から変更できます。標準のユーザー別Pythonインストール先も自動検出します。
MSVCの探索先を指定する場合は STUDYGADGET_VCVARS に vcvars64.bat の絶対パスを指定します。
VS Codeのビルドは tools/build_3ds.py から各ツールを直接起動します。PowerShellの実行ポリシーを変更する必要はありません。tools/build-3ds.ps1 も補助用に残しています。

## 検証範囲
3DSXとAndroid APKのビルド、実際のC UIの操作、更新ファイルのSHA-256検証・バックアップを検証しています。
ローカル接続を制限する実行環境のため、PCからスマホへの実送信、ブラウザー/VS Code上の最終表示、
実機での受信とRosalina再起動は未確認です。
単なるアップロード成功を実機更新成功とは報告しません。
